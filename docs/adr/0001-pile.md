# ADR 0001 — Pile technique et outillage qualité

- Statut : accepté
- Date : 2026-11-09

## Contexte

Désinstalleur Windows 10/11 personnel, ouvert ponctuellement puis fermé. Priorités : sûreté système, robustesse, réactivité pendant l'usage (fenêtre utilisable < 1 s, liste < 300 ms), mémoire < 150 Mo WebView2 compris. Thème et outillage partagés avec Viewer.

## Décision

- **Interface** : Tauri 2 (crate `tauri` 2.11.x, CLI 2.12.x, `@tauri-apps/api` 2.11.x), Svelte 5 en mode runes, Vite, sans SvelteKit. TypeScript 6.x strict (pas de TS 7 tant que svelte-check ne le prend pas en charge).
- **Cœur** : Rust édition 2024. `src-tauri/src/core/` ne dépend pas de `tauri`, ce qui le garde testable sans fenêtre et rend l'interface remplaçable.
- **Windows** : crate `windows` 0.62 (et non `windows-sys` comme Viewer), parce qu'il faut COM, WMI et WinRT (`PackageManager`). Tout `unsafe` vit dans `src-tauri/src/win/`, chaque bloc avec un commentaire `// SAFETY:` ; les lints `unsafe_op_in_unsafe_fn` et `clippy::undocumented_unsafe_blocks` sont en `deny`.
- **Types IPC générés** : `specta` 2.0.0-rc.26 + `tauri-specta` 2.0.0-rc.26 (fonctionnalités `derive`, `typescript`) + `specta-typescript` 0.0.13, versions exactes (`=`, imposées par `tauri-specta`). Ils génèrent les types **et** une fonction typée par commande dans `src/lib/ipc/bindings.ts` ; l'UI n'appelle jamais `invoke` directement et les noms de commandes ne sont jamais réécrits à la main. Un test `cargo test` échoue si le fichier généré n'est plus à jour.
  - Alternative écartée : `ts-rs` (stable, mais ne génère que les types : le nom de chaque commande et sa signature seraient dupliqués à la main côté TS, ce qui contredit la règle DRY).
  - Risque accepté : `tauri-specta` est en release candidate depuis longtemps. Atténuation : versions exactes, `bindings.ts` versionné dans git, et le seul couplage passe par `lib.rs` et `commands.rs` ; un retour à `ts-rs` + une table de commandes générée resterait local.
- **Qualité** : Biome (lint et formatage TS/JS), svelte-check `--fail-on-warnings`, Vitest, `cargo fmt`, `clippy -D warnings`, `cargo test`, regroupés dans `npm run verify` qui doit sortir à 0. `cargo deny check` (licences, avis RustSec) et `npm audit --omit=dev` en CI.
- **CI** : GitHub Actions, un job web (Ubuntu) et un job Rust (Windows), actions épinglées par SHA (mêmes SHA qu'Viewer à la date de cette ADR).
- **Profil release** : `lto = true`, `codegen-units = 1`, `opt-level = 3`, `strip = true`.
- **Dépendances** : versions épinglées ; toute nouvelle dépendance exige une ADR.

## Alternatives écartées

- **egui/eframe** : mémoire de repos plus faible, mais perte du thème et des composants communs, de l'accessibilité HTML et du flou natif ; la mémoire de repos compte peu pour une application ouverte ponctuellement.
- **fastframe** : v0.17, hors crates.io, s'appuie sur des forks d'egui et de winit.

## Conséquences

- WebView2 fixe un plancher mémoire ; il est mesuré dans `docs/perf.md` à chaque jalon.
- Sur la machine de développement, la compilation Rust exige les bibliothèques C++ x64 de MSVC (sinon erreur LNK1104).
